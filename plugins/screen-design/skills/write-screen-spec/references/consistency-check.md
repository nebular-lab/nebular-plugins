# 整合性チェックのプロンプト

画面設計書とワイヤーフレームを書いたり直したりしたあとに、サブエージェントへ渡して食い違いを探させるためのプロンプト。書いた本人は思い込みで見落としやすいので、別のエージェントに読ませる。

## 使い方

1. 下のプロンプトの `{...}` を埋めて、汎用のサブエージェントに渡す。
2. 返ってきた「エラー」を直し、もう一度チェックする。チェックは最大 3 回までにし、それでも残ったものは報告でユーザーに伝える。「警告」は内容を見て、直すか伝えるかを決める。

番号の正はワイヤーフレームにある。ワイヤーフレームの番号がおかしいときは、設計書で合わせ込まずに、ワイヤーフレームを直す。

## プロンプト

````text
あなたは画面設計書のレビュアーです。次のファイルを読み、食い違いと規則違反を探してください。ファイルは編集しないでください。

- 対象の画面: {画面 ID}
- 置き場所: {例: docs/screens/}（overview.md、messages.md、common-rules.md、あれば storage.md と、画面ごと・共通ヘッダーごとのフォルダがある。フォルダの中に、設計書とワイヤーフレームがある）
- OpenAPI 定義: {パス。なければ「なし」}
- 記述規則: {write-screen-spec/references/writing-rules.md の絶対パス}
- ワイヤーフレームの規則: {write-screen-wireframe/references/wireframe-rules.md の絶対パス}
- 書き方の手本: {examples/docs/screens/ の絶対パス}

最初に 2 つの規則を全部読み、手本を 1 画面分読んでください。そのうえで、何を確かめるべきかの観点を自分で洗い出してから、対象を読んでください。少なくとも次の向きで確かめます。

1. ワイヤーフレームが、ワイヤーフレームの規則に沿っているか。
2. ワイヤーフレームと設計書が合っているか（番号、部品、文言）。
3. 設計書の中で、互いに参照しているものが合っているか（部品番号、アクション ID、手順番号、メッセージ、クエリパラメータ、ブラウザストレージ）。手順どおりに動かしたときに、動きが決まらない箇所や、元に戻らない状態がないか。
4. 設計書が、記述規則と共有ファイル（overview.md、messages.md、common-rules.md、storage.md）に沿っているか。画面が使う共通ヘッダーの設計書と合っているか（指定した変数、ヘッダーに任せた表示や処理）。
5. 設計書が、OpenAPI 定義と合っているか。

次の形で、日本語で報告してください。「エラー」は直す必要があるもの、「警告」は確認したほうがよいものです。

## エラー
- [ファイル:行] 何が食い違っているか。どう直せばよいか。
## 警告
- [ファイル:行] ...
## 確かめた観点
- （自分で洗い出した観点を、問題がなかったものも含めて並べる）
````
