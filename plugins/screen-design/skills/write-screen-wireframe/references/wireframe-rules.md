# ワイヤーフレームの記述規則

ワイヤーフレームは「何が、どの順に、どこに並ぶか」を示す図。見た目は作り込まない。書き方の具体例は [サンプル](../../../examples/docs/screens/) の `SCR-NNN_*.html` を見る。規則にない判断をしたときは、サンプルに合わせ、ユーザーに伝える。

## 前提

- すべて PC 表示の前提で描く。
- 1 画面 1 ファイル。保存先の、画面ごとのフォルダ `SCR-NNN_<slug>/` の中の `SCR-NNN_<slug>.html`。フォルダ名とファイル名の ID と slug は、設計書と同じにする。
- 見た目は、保存先に 1 つ置いた共通の `wireframe.css` だけで決める（画面のフォルダからは `../wireframe.css`）。`<head>` は [template.html](../assets/template.html) のままにし、`<title>` だけ変える。
- `style` 属性、`<style>`、`<script>`、独自のクラス、外部の画像は使わない。見た目の自由度を上げると、実装の議論に寄っていくため。`wireframe.css` で表せないものは、`.note` に言葉で書く。

## 使える要素

HTML の要素をそのまま使い、フォームの部品は本物の `input` や `select` を使う。使えるクラスは [wireframe.css](../assets/wireframe.css) にあるものだけ（画面の枠、横並び・縦並び・列、領域、入力欄のまとまり、エラー表示、画像・アイコン、タブ、言葉での説明、モーダルなど）。組み合わせ方はサンプルに合わせる。

状態を表す属性（`value`、`placeholder`、`checked`、`selected`、`disabled`）は使ってよい。

## 部品番号

番号は設計書の No と共通。ワイヤーフレームで振った番号を、設計書でもそのまま使う。

- 番号を振る要素に `data-no` を付ける。1 から始まる整数の通し番号だけを使い、枝番は使わない。
- 振り順は、画面の上から下、同じ高さなら左から右。まとまりに振ったら、その中の部品に続きの番号を振る。
- 番号を振るのは、利用者が見る・操作する部品。画面に見える文字・アイコン・画像・入力欄・ボタンは、漏れなく、どれかの番号の付いた要素にする。レイアウトのための要素には振らない。
- まとまり（ヘッダー、フッター、確認ダイアログ、タブ、選択肢のまとまりなど）に番号を振っても、その中の文言や部品（ヘッダーのサービス名、ダイアログの見出しと文、1 つ 1 つのタブ、1 つ 1 つの選択肢）には、別に番号を振る。
- 番号がなくてよいのは、次のものだけ。図の説明として書いた `.note`、繰り返す部品の 2 行目以降（「…」で続きを示す行を含む）、ほかの状態の `.screen` ですでに番号を振った部品の再掲。
- 項目名（見出し・ラベル）とデータは、別々の番号にする。フォームの見出しと入力欄、表の見出しのセルとデータのセル、「主催」と名前、のどれも同じ。1 つの要素にまとめない。
- `input` や `select` には番号が表示されないので、それを包む要素に付ける。
- アイコンや画像にも振る（文言がないので、設計書で読み上げ名を決めるため）。飾りのものも同じ。
- 繰り返す部品（一覧の行）は、1 行目の中の部品にだけ振る。

## 状態

- 通常の状態を、最初の `.screen` に描く。見た目が大きく変わる状態（読み込み中、データなし、モーダル表示など）は、`.screen` を並べて描き、`data-title` に状態名を書く。
- 2 つ目以降の `.screen` では、その状態で初めて出る部品にだけ番号を付ける。
- 通常の部品と並んで出る部品（選択によって出し分ける入力欄など）は、画面上の位置に合わせて番号を割り込ませる。通常の部品に置き換わって出る部品と、重ねて出す部品（モーダル）は、最後の番号の続きを振る。

## エラー表示と確認ダイアログ

- 画面の中に出すエラーメッセージは、出す場所を部品として描く（`.error`）。あとから足すと番号がずれるので、下書きの時点で、画面上部に 1 つと、すべての入力項目の下に 1 つずつ描いておく。要らないと決まったものは、ユーザーに確認して消す。
- エラー表示は最初は出ていないが、位置と番号がわかるように、通常の状態の `.screen` に描く。
- 画面の中に出す確認ダイアログは、すべて描く。ダイアログと、その中の見出し・文・ボタンに、それぞれ番号を振る。
- トーストと、ブラウザ標準の確認は描かない。

## 中身の文字

- ラベル・ボタン名・見出しは、実際に表示する文言で書く。必須の印（「（必須）」など）を表示するなら、見出しの文言として書く。
- 一覧や表のデータは、それらしい例を 2〜3 件入れる。
- 決まっていない文言は `TBD` と書く。

## モーダルだけの画面

独立した操作があり、別の画面 ID を振るモーダルは、`.screen` の中に親画面を示す `.note` だけを置き、その上にモーダルを重ねて描く。親画面の部品は描かない。番号は、ダイアログを 1 番にする。
