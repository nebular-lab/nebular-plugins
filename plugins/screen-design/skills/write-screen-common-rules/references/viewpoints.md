# 共通ルールの項目

共通ルール（`common-rules.md`）に書く項目と、その選択肢の一覧。どの画面でも同じになる扱いを、ここに並べた項目ごとに、選択肢から 1 つ選んで決める。誰が作っても同じ形になるように、節・項目・選択肢は、この一覧のとおりにする。

## 書き方

- 選択肢のある項目は、節ごとに `| 項目 | 設定 | 選択肢 |` の表を置き、1 項目 1 行で書く。節と項目の順序は、この一覧の順にする。
- 「設定」には、選択肢のどれか 1 つを、そのままの文字で書く。文章で書き足さない。選択肢が「ミリ秒の数値」「回数」のときは、数だけを書く（`300000`、`3`）。決まっていない項目は `TBD`。
- 「選択肢」には、この一覧の選択肢を ` / ` で区切って書く（読む人が、ほかに何を選べたかがわかるようにするため）。
- 選択肢のないルール（「選択肢のないルール」の節）は、選択肢のある節のあとに箇条書きで置く。文は変えない。
- ライブラリの設定（react-hook-form、TanStack Query）の節は、いちばん最後に置く。節の最初に「対象のバージョン」を 1 行で書き、表には「ライブラリの既定値」の列を足す（`| 項目 | 設定 | ライブラリの既定値 | 選択肢 |`）。既定値と違う設定にしたことが、表を見てわかるようにするため。プロジェクトで使うバージョンが違うときは、バージョンの行を直し、既定値がそのバージョンでも同じかを確かめる。
- `common-rules.md` の節の順序は、入力、表示形式、一覧、送信、遷移、アクセシビリティ、react-hook-form のデフォルト設定、TanStack Query の設定（defaultOptions）。
- 項目や選択肢を足したり、名前を変えたりしない。足したいものがあれば、ユーザーに相談してこの一覧を直す。
- ある画面だけ共通ルールと違う扱いにするときは、共通ルールには書かず、その画面の設計書に書く。

## 項目と選択肢

### 入力

| 項目 | 選択肢 | 意味 |
| --- | --- | --- |
| 改行を 1 文字と数えるか | `yes` / `no` | 文字数を数えるとき、改行を 1 文字に含めるか |
| 文字数のバリデーション時に前後の空白を取り除くか | `yes` / `no` | `yes` なら、前後の空白を除いた長さで文字数をチェックする |
| 送信時に前後の空白を取り除くか | `yes` / `no` | `yes` なら、API に送る値から前後の空白を除く |
| 入力可能文字種・入力可能最大文字数のある項目への貼り付け | `収める` / `受け付けない` | `収める`: 上限を超える分を切り詰め、入力できない文字を取り除いて入れる。`受け付けない`: 範囲に収まらない貼り付けは、何も入れない |
| 日本語入力（IME）の変換を確定する前の文字にも、入力の制限とバリデーションを行うか | `yes` / `no` | 日本語を入力している途中の、変換を確定する前の文字（「東京」と入力する途中の「とうきょう」など）の扱い。`no` なら、確定するまでは入力可能文字種・入力可能最大文字数の制限もバリデーションも行わず、確定した文字に対して行う。`yes` なら、途中の文字にもその都度行う（上限が 2 文字の欄で「とうきょう」と打てず、「東京」を入力できなくなることがある） |

### 表示形式

| 項目 | 選択肢 | 意味 |
| --- | --- | --- |
| 数値を 3 桁ごとにカンマで区切るか | `yes` / `no` | 件数・金額などの数値の表示 |

### 一覧

| 項目 | 選択肢 | 意味 |
| --- | --- | --- |
| 再読み込みやブラウザの戻るで一覧に戻ったときに、検索条件とページを復元するか | `yes` / `no` | 一覧で検索やページ送りをしたあと、ページを再読み込みしたとき、または別の画面へ移ってからブラウザの戻るで一覧に戻ったときの扱い。`yes` なら、検索条件とページを URL クエリに持っておき、同じ条件・同じページの一覧を表示する。`no` なら、条件のない 1 ページ目に戻る |

### 送信

| 項目 | 選択肢 | 意味 |
| --- | --- | --- |
| 送信中にボタンを非活性にするか | `yes` / `no` | `yes` なら、API を呼ぶボタンを、応答が返るまで非活性にする |

### 遷移

| 項目 | 選択肢 | 意味 |
| --- | --- | --- |
| 未保存の変更があるときに離脱確認をするか | `yes` / `no` | `yes` なら、入力内容に変更があるまま画面を離れようとしたときに確認を出す |

### react-hook-form のデフォルト設定

フォームは react-hook-form で作る前提で、`useForm` に渡す設定を、API の名前と値のまま書く。対象のバージョンは v7。

| 項目 | 選択肢 | ライブラリの既定値 | 意味 |
| --- | --- | --- | --- |
| `mode` | `onChange` / `onBlur` / `onSubmit` / `onTouched` / `all` | `onSubmit` | 最初の送信の前に、いつバリデーションを行うか。`onChange`: 入力するたび。`onBlur`: フォーカスが外れたとき。`onSubmit`: 送信時だけ。`onTouched`: その項目から最初にフォーカスが外れたときにチェックし、それ以降は入力するたび。`all`: フォーカスが外れたときと入力するたびの両方 |
| `reValidateMode` | `onChange` / `onBlur` / `onSubmit` | `onChange` | 一度送信してエラーが出たあと、いつバリデーションをやり直すか。`onSubmit` なら、もう一度送信するまでエラーの表示は変わらない |

どの設定でも、送信時にはすべての項目をチェックする。

### TanStack Query の設定（defaultOptions）

API の取得と更新は TanStack Query で行う前提で、対象のバージョンは v5（`@tanstack/react-query`）。`QueryClient` の `defaultOptions` に渡す設定を、API の名前と値のまま書く。ここに書くのは既定の設定だけにする。画面ごと・API ごとの設定（`queryKey`、個別の `staleTime` など）は書かない。

| 項目 | 選択肢 | ライブラリの既定値 | 意味 |
| --- | --- | --- | --- |
| queries の `staleTime` | `0` / `Infinity` / ミリ秒の数値 | `0` | 取ったデータを新しいとみなす時間。この間は取り直さない。`0` なら、下のきっかけのたびに取り直す |
| queries の `gcTime` | ミリ秒の数値 / `Infinity` | `300000`（5 分） | 使われなくなったデータを捨てるまでの時間。この間に同じ画面へ戻ると、前のデータがすぐ表示される |
| queries の `refetchOnMount` | `true` / `false` / `'always'` | `true` | 画面を開いたとき、古くなったデータを取り直すか |
| queries の `refetchOnWindowFocus` | `true` / `false` / `'always'` | `true` | 別のタブやアプリから戻ってきたとき、古くなったデータを取り直すか |
| queries の `refetchOnReconnect` | `true` / `false` / `'always'` | `true` | 通信が回復したとき、古くなったデータを取り直すか |
| queries の `retry` | `false` / 回数 | `3` | 取得に失敗したとき、自動でやり直す回数。`false` ならやり直さず、すぐにエラーの処理をする |
| mutations の `retry` | `false` / 回数 | `0` | 保存・削除に失敗したとき、自動でやり直す回数 |

## 選択肢のないルール

あったほうがよいことは、選ばせずに、決まったルールとして `common-rules.md` に書く。雛形にある文をそのまま置き、ユーザーには聞かない。プロジェクトの事情で外したいルールがあるとユーザーが言ったときだけ、その行を消す。

### アクセシビリティ

| ルール | 補足 |
| --- | --- |
| 入力項目のエラー表示の内容は、その入力項目の説明として伝える（その入力項目にフォーカスしたときに、エラーの内容も読み上げられる） | 画面を見ていない利用者が、どの項目の何がエラーなのかをわかるようにする |
| 入力項目に結び付かないエラー表示（画面上部のエラーなど）を表示したときは、読み上げで通知する | 結び付く入力項目がないので、表示したことそのものを伝える |
| トーストを表示したときは、読み上げで通知する | 保存できたかどうかが伝わるようにする |
| 送信時にエラーがあるときは、最初のエラー項目にフォーカスを移す | 最初のエラー項目とは、エラーのある入力項目のうち、部品番号がいちばん小さいもの |
| 確認ダイアログを開いたときは、フォーカスをダイアログの中の最初のボタンに移す | 別のボタンに置きたいダイアログは、設計書の備考に `初期フォーカス: No.33` と書く |
| 確認ダイアログを閉じたときは、そのダイアログを開いたボタン・リンクにフォーカスを戻す | 閉じたあと画面に残る場合だけ |
| 確認ダイアログは Esc キーで閉じられる。やめる側のボタン（「キャンセル」など）を押したときと同じ処理をする | 処理中で、やめる側のボタンが非活性のときは閉じない |
| 一覧を取り直したとき（検索、ページ送りなど）は、結果（件数、または 0 件のときの文言）を読み上げで通知する | 結果が変わったことが伝わるようにする |
| Tab キーでフォーカスが移る順序は、部品番号の順にする | 部品番号は、画面の上から下、左から右に振っている |
| 文言のない部品（アイコンだけのボタン、画像）には、読み上げ名を付ける | 読み上げ名は、設計書の画面項目の備考に `読み上げ名: …` と書く |

ルールは「利用者に何が起きるか」だけで書く。どの属性（`role`、`aria-*`）や部品で実現するかは書かない。使うコンポーネントライブラリによって実現のしかたが違っても、結果が同じならよい、とするため。

色のコントラスト、文字の大きさ、押せる領域の広さは、見た目のデザインで決めることなので、ここでは扱わない。

## 画面設計書との関係

共通ルールは、画面設計書を書くときの既定になる。

- 設計書に書く欄があること（バリデーションのタイミング、ボタンの非活性、離脱確認、数値の表示形式、一覧の検索条件の復元）は、設計書にも共通ルールのとおりに書く。「共通ルールのとおり」と略さない。設計書だけを読んでも動きがわかるようにするため。
- 設計書に書く欄がないこと（「入力」の節の項目）は、設計書には書かない。共通ルールがそのまま適用される。
- 選択肢のないルール（アクセシビリティ）は、設計書の手順には書かない。どの画面にもそのまま適用される（設計書に書くのは、備考の `読み上げ名: …` と、ダイアログの `初期フォーカス: …` だけ）。
- TanStack Query の設定は、設計書には書かない。設計書の「〜を呼ぶ」は、この設定のもとで取り直しが必要なときに呼ぶ、という意味になる。
- ある画面・ある項目だけ共通ルールと違う扱いにするときは、その画面の設計書に書く（バリデーションのタイミングなら、そのタイミングのアクションを立てる。欄のないことは、備考に `共通ルールと違う: …` と書く）。
