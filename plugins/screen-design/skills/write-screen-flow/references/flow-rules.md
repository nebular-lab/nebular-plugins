# 画面遷移図の描き方

画面設計書（`SCR-NNN_<slug>.md`）から、draw.io の画面遷移図（`screen-flow.drawio`）を作るための規則。誰が作っても同じ図になるように、何を描くか、どの形で描くか、XML をどう書くかを決めておく。迷ったら [サンプル](../../../examples/docs/screens/screen-flow.drawio) に従う。

図の目的は、「どの画面の、どのボタンやリンクから、どの画面へ移るか」を 1 枚で見渡せるようにすること。図は簡単に保ち、処理・条件・確認ダイアログは描かない。それらは画面設計書のアクションを読めばわかる。

## 何を描くか

設計書の「6. アクション」から、ボタンやリンクを押した結果、別の画面へ移るものを拾う。

| 描くもの | 例 |
| --- | --- |
| 押すと画面を移るだけのアクション | 「← 一覧へ戻る」リンク押下 → イベント一覧へ遷移する |
| 処理が成功すると別の画面へ移るアクション | 「公開する」ボタン押下 → API が成功するとイベント一覧へ遷移する |
| 確認のあとに別の画面へ移るアクション | 「削除」ボタン押下 → 確認で「削除する」を押し、成功するとイベント一覧へ遷移する |
| 部品のない操作で別の画面へ移るもの | ブラウザの戻るで前の画面へ移る、など（設計書に遷移先が書かれている場合だけ） |

確認ダイアログの中のボタン（「削除する」「離れる」など）のアクションに遷移が書かれている場合は、ダイアログの中のボタンではなく、そのダイアログを表示するアクションの対象（「削除」ボタン、「← 一覧へ戻る」リンク）をきっかけとして描く。

描かないもの:

- 処理、条件、確認ダイアログ。きっかけから遷移先へ、矢印を 1 本引くだけにする。
- エラーのときの遷移（権限がない、見つからない、401 など）と、初期表示時の処理で自動的に起きる遷移。これらは「図に描いていない遷移」のメモにまとめる。
- 画面が変わらない操作（エラーを表示して画面に残る、表示を切り替える）と、同じ画面への遷移（保存したあと同じ画面を開き直す、など）。
- 廃止した画面（`overview.md` の画面一覧で、画面名に `（廃止）` が付いたもの）と、そこへの遷移。
- 遷移のきっかけにならない部品。

1 つのきっかけが、場合によって別々の画面へ移る（新規作成なら A、編集なら B）ときは、それぞれへ矢印を引き、矢印に場合を短いラベルで付ける（`新規作成`、`編集`）。

画面一覧（`overview.md`）にあるが設計書がまだない画面は、枠だけを描く（きっかけは置かない）。画面一覧にない遷移先（ログイン、ヘルプなど）は、「外部・設計書のない画面」として描く。

## 部品と形

| 種類 | 形 | 書く内容 |
| --- | --- | --- |
| 画面 | 枠（スイムレーン）。水色 | 1 行目に `画面 ID 画面名`、2 行目以降に URL |
| 遷移のきっかけ（ボタン） | 画面の枠の中の、角の丸い四角 | ボタンの文言を「」で |
| 遷移のきっかけ（リンク） | 画面の枠の中の、下線付きの四角 | リンクの文言を「」で。文言が API の値なら項目名（`タイトル`） |
| 部品のない操作 | 画面の枠の中の、楕円 | 操作名（`ブラウザの戻る`） |
| 外部・設計書のない画面 | 灰色の点線の四角 | 名前と URL（決まっていなければ `URL は TBD`） |
| メモ | 右上の折れた四角 | 「図に描いていない遷移」と凡例 |

ボタンかリンクかは、設計書の「ボタン・リンク」の表の「タグ」で決める（`button` はボタン、`a` はリンク）。

## 遷移の描き方

きっかけから遷移先の画面の枠へ、矢印を 1 本引く。

- 矢印にラベルは付けない。ただし次の場合だけ、短いラベルを付ける。
  - 同じ画面へ、複数のきっかけから別の形で移るとき（`新規作成`、`編集`）
  - 1 つのきっかけが、場合によって別々の画面へ移るとき（場合を書く）
  - 別タブで開くとき（`別タブ`。矢印は点線にする）
- ステータス（`[201]`）、条件（`変更があるとき`）、確認の文言、API は書かない。
- 同じきっかけから同じ画面へ移る遷移は、場合が複数あっても矢印を 1 本にする。

## 図に描いていない遷移

エラーのときの遷移と、初期表示時の処理で自動的に起きる遷移は、図の左上のメモにまとめて書く。図に矢印を引くと、どの画面からも同じ場所へ矢印が伸びて読みにくくなるため。

```
図に描いていない遷移
・どの画面でも、API が 401 を返したら → ログイン（/login）
・SCR-002 イベント編集: 権限がないとき、イベントが見つからないとき → SCR-001 イベント一覧
```

- すべての画面で同じになるものは「どの画面でも」とまとめて 1 行にする。
- 画面ごとに違うものは、画面ごとに 1 行にする。条件は短く書き、細かい条件（ステータスなど）は書かない。

## 文言

- 画面は `画面 ID 画面名` で書く。
- ボタン・リンクの文言は、設計書（ワイヤーフレーム）の文言をそのまま「」で書く。条件で文言が変わるボタンは、`「公開する」／「更新する」` のように並べる。
- メッセージ ID やアクション ID は書かない。

## 配置

draw.io で手で直すことを前提に、最初の配置は次のとおりにする。きれいに自動配置することより、決まった場所に置くことを優先する。画面が多い図では矢印が重なったり枠を横切ったりするが、ここでは整えきらず、draw.io で直してもらう（更新しても位置は保たれる）。

- 画面の枠は、画面 ID の順に左から右へ、上端をそろえて並べる。最初の枠の左上は (340, 140)。枠の幅は 240。枠と枠の間は 240 空ける（2 つ目の枠の x は 820）。画面が多いときは、5 画面ごとに段を変える（段の間は 120 空ける）。
- 外部・設計書のない画面は、いちばん左の列（x は 40）に縦に並べる。幅は 220、高さは 50。そこへ向かうきっかけと同じ高さに置けるなら、そろえる。置けなければ、上から 10 ずつ空けて並べる。
- 画面の枠の中のきっかけは、上から、設計書の部品番号の順、部品のない操作の順に置く。大きさは幅 180、高さ 30。枠の左上から見て x は 30、y は最初が 80 で、以降 60 ずつ下げる。枠の高さは、きっかけがいちばん多い画面の、最後のきっかけの下に 50 の余白ができる高さにし、同じ段の画面で同じにする。
- 画面から画面への矢印は、きっかけから水平に出して、遷移先の枠の縦の辺に、同じ高さで入れる（まっすぐな線になる）。右の画面へ向かう矢印は、きっかけの右の辺の上寄り（高さの 1/4）から出す。左の画面へ向かう矢印は、きっかけの左の辺の下寄り（高さの 3/4）から出す。向きの違う矢印が同じ線の上で重ならないようにするため。
- 外部・設計書のない画面への矢印は、きっかけの左の辺の中央から出して、外部の四角の右の辺の中央に入れる（`exitX=0;exitY=0.5;entryX=1;entryY=0.5`）。
- 隣り合っていない画面へ向かう矢印は、間の画面の枠の上か下を通るように経由点を置く。
- 「図に描いていない遷移」のメモは左上（左上が (40, 30)、幅 640）、凡例はいちばん下の枠の下（x は 40、枠の下端から 40 空ける。幅 640）に置く。

## XML の書き方

draw.io のファイルは、圧縮しない XML で書く（差分が読めるようにするため）。

```xml
<mxfile host="app.diagrams.net">
  <diagram id="screen-flow" name="画面遷移図">
    <mxGraphModel dx="1600" dy="900" grid="1" gridSize="10" guides="1" tooltips="1" connect="1" arrows="1" fold="1" page="0" pageScale="1" math="0" shadow="0">
      <root>
        <mxCell id="0" />
        <mxCell id="1" parent="0" />
        <!-- ここに部品と矢印を書く -->
      </root>
    </mxGraphModel>
  </diagram>
</mxfile>
```

- 文言の改行は `&lt;br&gt;` で書く（`html=1` のスタイルを使う）。`<`、`>`、`&`、`"` は XML のエスケープをする。
- 画面の中のきっかけは、`parent` を画面の枠の ID にし、位置を枠の左上からの相対で書く。それ以外の部品と矢印は `parent="1"`。
- 矢印は `edge="1"` にし、`source` にきっかけの ID、`target` に遷移先の画面（または外部）の ID を書く。

**ID**

更新しても同じ部品が同じ ID になるように、意味のある ID を付ける。

| 部品 | ID | 例 |
| --- | --- | --- |
| 画面 | `scr-NNN` | `scr-002` |
| きっかけ（部品） | `scr-NNN-no-X`（X は設計書の部品番号） | `scr-002-no-36` |
| 部品のない操作 | `scr-NNN-op-名前` | `scr-002-op-back` |
| 外部 | `ext-名前` | `ext-help` |
| 矢印 | `e-<きっかけの ID>-<遷移先の ID>` | `e-scr-002-no-36-scr-001` |
| メモ | `note-hidden`（図に描いていない遷移）、`note-legend`（凡例） | |

**スタイル**

| 部品 | style |
| --- | --- |
| 画面 | `swimlane;whiteSpace=wrap;html=1;startSize=60;collapsible=0;fillColor=#dae8fc;strokeColor=#6c8ebf;fontStyle=1;` |
| ボタン | `rounded=1;whiteSpace=wrap;html=1;fillColor=#ffffff;strokeColor=#333333;` |
| リンク | `rounded=0;whiteSpace=wrap;html=1;fillColor=#ffffff;strokeColor=#333333;fontStyle=4;` |
| 部品のない操作 | `ellipse;whiteSpace=wrap;html=1;fillColor=#f5f5f5;strokeColor=#666666;` |
| 外部 | `rounded=0;whiteSpace=wrap;html=1;dashed=1;fillColor=#f5f5f5;strokeColor=#666666;` |
| メモ | `shape=note;whiteSpace=wrap;html=1;size=14;align=left;verticalAlign=top;spacing=8;fillColor=#ffffff;strokeColor=#999999;` |
| 矢印 | `edgeStyle=orthogonalEdgeStyle;rounded=0;html=1;endArrow=block;endFill=1;` |
| 矢印（別タブ） | 矢印の style に `dashed=1;` を足す |

矢印の出入り口は、style に `exitX=1;exitY=0.25;exitDx=0;exitDy=0;entryX=0;entryY=0.26;entryDx=0;entryDy=0;` のように足す（0〜1 の割合。`entryY` は、矢印の高さが枠の上端から何割の位置かを計算する）。経由点は `<Array as="points"><mxPoint x="..." y="..." /></Array>` で書く。

## 更新するとき

すでに `screen-flow.drawio` があるときは、作り直さずに更新する。ユーザーが draw.io で配置を直しているかもしれないため。

1. 先に、きっかけの ID を付け替える。設計書の部品番号は、部品を足したり消したりするとずれるので、ID（`scr-NNN-no-X`）が同じでも同じ部品とは限らない。
   - 図にあるきっかけと、設計書から拾ったきっかけを、同じ画面の中で、文言（図の `value` と、設計書の項目名）が同じものどうしで対応させる。
   - 対応したきっかけの部品番号が変わっていたら、ID を新しい番号に付け替える。そのきっかけから出る矢印の ID と `source` も付け替える。位置は変えない。
   - 文言が同じきっかけが同じ画面に複数あるとき、文言も変わっているときは、対応を決めきれない。推測した対応をユーザーに見せて確認する。
2. ID が同じ部品（付け替えたあと）は、位置と大きさ（`mxGeometry`）を変えない。矢印の出入り口（`exitX`、`exitY`、`entryX`、`entryY`）と経由点も変えない。文言と、出入り口以外の style だけを設計書に合わせて直す。
3. 新しい部品だけを、配置の規則に従って足す。置く場所がほかの部品と重なるなら、空いている場所にずらす。きっかけが増えて枠に入りきらないときは、枠の高さだけを伸ばしてよい。
4. 設計書からなくなった遷移の部品と矢印は消す。
5. ID の規則に合わない部品（ユーザーが手で足したもの）は消さずに残し、報告で伝える。

## 描き終えたら確かめること

- XML として正しい（`python3 -c "import xml.dom.minidom,sys; xml.dom.minidom.parse(sys.argv[1])" <ファイル>` が通る）。
- ID が重複していない。矢印の `source` と `target` が、どれも存在する ID を指している。
- 設計書から拾った遷移が、すべて図にある（拾った遷移の一覧と、矢印を 1 つずつ突き合わせる）。図にあって設計書にない遷移がない。
- 処理・条件・確認ダイアログの部品や、ステータス・条件のラベルを描いていない。同じ画面への遷移と、廃止した画面を描いていない。
- 画面一覧（`overview.md`）の画面（廃止したものを除く）が、すべて枠として描かれている。
- 遷移先の画面 ID・画面名・URL、ボタンやリンクの文言が、設計書と合っている。きっかけの ID の部品番号が、設計書の今の部品番号と合っている。
- エラーのときの遷移と、初期表示での自動の遷移が、「図に描いていない遷移」のメモにある。
