# 画面遷移図の描き方

画面設計書から、draw.io の画面遷移図（`screen-flow.drawio`）を作るための決まり。部品の形、スタイル、ID、配置の具体例は [サンプル](../../../examples/docs/screens/screen-flow.drawio) に合わせる。

## 何を描くか

図の目的は、「どの画面の、どのボタンやリンクから、どの画面へ移るか」を 1 枚で見渡せるようにすること。図は簡単に保つ。

- 画面を枠で描き、その中に、別の画面へ移るきっかけ（ボタン、リンク、部品のない操作）を置く。きっかけから遷移先の画面へ、矢印を 1 本引く。
- 処理、条件、確認ダイアログは描かない。それらは設計書のアクションを読めばわかる。確認ダイアログの中のボタンで遷移するときは、そのダイアログを開く、もとのボタンやリンクをきっかけにする。
- 画面が変わらない操作と、同じ画面への遷移は描かない。廃止した画面も描かない。
- エラーのときの遷移（権限がない、見つからない、401 など）と、初期表示時の処理で自動的に起きる遷移は、矢印にせず、「図に描いていない遷移」のメモにまとめる。どの画面からも同じ場所へ矢印が伸びて、読みにくくなるため。
- 共通ヘッダーの中のボタンやリンクによる遷移は、矢印にしない。どの画面からも同じ場所へ矢印が伸びるため。必要なら「図に描いていない遷移」のメモに書く。
- 画面一覧にない遷移先（ログイン、外部のサイトなど）は、外部として描く。
- 矢印のラベルは、付けないと区別できないときだけ、短く付ける（別タブで開く、場合によって行き先が違う、など）。ステータスや条件は書かない。
- 文言は設計書のとおりに書く。メッセージ ID やアクション ID は書かない。

## ファイルの書き方

- 圧縮しない XML で書く（差分が読めるようにするため）。
- 更新しても同じ部品が同じ ID になるように、意味のある ID を付ける（画面 ID、きっかけの部品番号、遷移元と遷移先）。
- draw.io で手で直すことを前提に、最初の配置は、決まった場所に置くことを優先する（画面 ID の順に並べ、きっかけは部品番号の順に並べる）。きれいに整えきらなくてよい。

## 更新するとき

すでにファイルがあるときは、作り直さずに更新する。ユーザーが draw.io で配置を直しているかもしれないため。

- 設計書の部品番号は、部品が増減するとずれる。先に、図のきっかけと設計書のきっかけを文言で照合し、番号が変わっていたら ID を付け替える。対応を決めきれないものは、ユーザーに確認する。
- 残る部品の位置・大きさ・矢印の経路は変えない。文言だけを設計書に合わせる。
- 新しい部品だけを足し、設計書からなくなった遷移は消す。
- ユーザーが手で足した部品（ID の付け方が違うもの）は消さずに残し、報告で伝える。

## 描き終えたら確かめること

- XML として正しく、ID が重複せず、矢印の両端が存在する部品を指している。
- 設計書から拾った遷移と、図の矢印が 1 対 1 で合っている。
- 画面一覧の画面（廃止を除く）が、すべて枠として描かれている。
